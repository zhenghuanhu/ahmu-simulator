# AHMU 仿真器功能实现内容描述

> 本文档以文字描述当前代码实现的各功能（技术文档「4.3 AHMU 仿真器」章节 4.3.1 ~ 4.3.20）的实现内容，采用「应具备…支持…能够…」句式。
>
> 仅描述**已确认完成并经代码核验**的内容；部分覆盖/硬件项/待确认处已在对应条目标注。

---

## 4.3.1 共享内存 / API

AHMU 仿真器应具备共享内存交互功能，支持通过 mmap 共享内存 + 环形缓冲区实现与系统试验软件平台之间的高效数据交互，能够按 `a664` / `a429` / `control` / `status` 四个区域分区读写，支持双向数据交互与环形缓冲覆盖写入。

## 4.3.2 打印管理

AHMU 仿真器应具备打印管理功能，支持通过 ARINC744A 打印协议向打印机下发打印数据，能够按 150 字节分块发送、处理 ACK 确认与 NAK 重发（最多 3 次），支持无外部打印机时由仿真器内置模拟打印生成 ps 文件与打印结果。

## 4.3.3 地面人机界面

AHMU 仿真器应具备地面人机界面功能，支持通过 Web 界面（Vue 3 + Element Plus）提供故障诊断、参数监控、飞机状态等功能的交互操作入口，能够实时展示系统状态与各类业务数据，支持中英文标签切换。（⚠️ 本功能为界面性功能，无独立可量化性能指标，需依据技术文档原条款确认指标口径）

## 4.3.4 维护模式

AHMU 仿真器应具备维护模式管理功能，支持基于「轮载=地 / 空速<80kts / 维护开关∈{地面测试,数据加载}」三条件同时满足判定进入维护模式，能够对维护条件持续 30 秒计时并自动切换，支持正常模式与维护模式的快速切换及状态查询。

## 4.3.5 通信安全

AHMU 仿真器应具备通信安全防护功能，支持 CRC32 校验（数据包/文件末尾追加，错误则丢弃）、VPN 加密隧道（AES-256-GCM）建立与拆除，能够进行 WiFi 白名单管理（可信 SSID + WPA2-PSK）与可信网络接入认证，支持安全事件日志记录。

## 4.3.6 故障诊断

AHMU 仿真器应具备故障诊断功能，支持接收 400 个成员系统（每成员 6 条故障模型）上报的故障/失效报告，能够进行故障方程级联过滤、FDE 驾驶舱效应关联修正，支持与/或逻辑运算定位根源故障并生成失效报告，支持 512 航段（每航段 2500 条）的故障存储与历史查询。

## 4.3.7 飞机状态消息

AHMU 仿真器应具备飞机状态消息功能，支持生成并发布飞机状态信息（1Hz 周期），能够接收轮载、空速及飞管信息（8 个双源参数，左源失效自动切换右源），支持对飞行航段、飞行阶段（1~15）及全局终止标志的计算与发布。

## 4.3.8 启动测试

AHMU 仿真器应具备启动测试功能，支持按 ARINC624 协议模拟与成员系统的启动测试交互通信，能够经交互式页面触发成员系统执行测试，支持交互式/非交互式两种测试场景，支持指令前与执行期间的成员抑制条件监视及测试结果判定。

## 4.3.9 发动机配平

AHMU 仿真器应具备发动机配平功能，支持对 4 台发动机的 N1 转速配平（配平值范围 ±2.5% N1），能够接收地面 HMI / 驾驶舱 / PMAT 三来源配平指令，支持左右配平通道、每发动机并发控制与 200ms 配平数据上报。

## 4.3.10 数据重置

AHMU 仿真器应具备数据重置管理功能，支持从配置文件读取启用 NVM 重置服务的成员系统列表（52 个成员），能够执行 full / partial / fault_history 三类重置，支持最多 5 个并发重置、重置结果接收存储与日志记录，并响应用户打印指令输出重置结果。

## 4.3.11 生命周期

AHMU 仿真器应具备生命周期管理功能，支持接收飞控模块（FCS_OutputData_TO_OMS_BLK_5，28 字节 / 400ms / VL 21162）的上电运行时间与上电循环计数数据，能够存储并查询成员系统的生命周期数据与获取日志。

## 4.3.12 参数监控

AHMU 仿真器应具备参数监控功能，支持参数基本配置管理（名称/类型/采样频率/精度/单位/是否记录/是否显示等），能够获取参数报告并下发，支持参数有效性校验与按 ATA 章节查询，支持参数快捷访问列表（100 张 × 每张 50~64 参数，哈希索引 O(1) 访问）。

## 4.3.13 构型管理

AHMU 仿真器应具备构型管理功能，支持周期性接收 400 个成员系统的构型报告（7 类构型项），能够与飞机基本构型比对并在不一致时生成构型错误报告，支持 ACR 飞机构型报告查询（硬件/软件/特定数据/软件部件四类）与维护人员主动请求。

## 4.3.14 数据下载

AHMU 仿真器应具备数据下载管理功能，支持从人机界面接收成员系统 NVM 数据获取指令，能够实时显示获取进度，支持 NVM 数据（1KB~256KB）存储与下载日志记录，并支持下载到 PMAT 与打印获取结果。

## 4.3.15 维护接口板

AHMU 仿真器应具备维护接口板功能（硬件项），支持通过工控机千兆以太网口（符合 IEEE802.3）提供维护接口。（🚫 本项为硬件交付项，无独立软件实现，需确认工控机硬件配置）

## 4.3.16 ACARS

AHMU 仿真器应具备 ACARS 数据链通信功能，支持通过 ARINC619 协议接收 CPM 转发的上行链路请求（EOR 标识）并触发下行维护数据，能够下发故障/失效/FDE/构型/事件五类报告（每类最多 20 条），支持 ACK 确认与无 ACK 重发（最多 3 次）。

## 4.3.17 人机界面

AHMU 仿真器应具备人机界面功能，支持各功能独立 Web 页面（系统总览/故障诊断/参数监控/ACARS/打印等 20+ 页面），能够提供维护人员的交互操作界面。（⚠️ 缺「数据上传」独立页面，「连续参数」是否并入参数监控页面待明确）

## 4.3.18 配置文件读取与模型解析

AHMU 仿真器应具备配置文件读取与模型解析功能，支持从配置文件读取数据重置启用成员列表（`nvm_reset_config.json`）。（⚠️ 其余故障诊断/启动测试/构型报告/生命周期模型为代码内置生成，未从 OHMS 维护模型配置工具输出的配置文件加载）

## 4.3.19 ICD 导入

AHMU 仿真器应具备 ICD 导入功能，支持解析 ICD 文件（JSON/XML）为 ICD 条目，能够生成 msgpack 二进制序列化快照缓存以加速后续启动加载，支持成员系统与消息帧的查询。

## 4.3.20 功能模型生成

AHMU 仿真器应具备功能模型生成功能，支持生成故障模型、FDE 驾驶舱效应消息池、ACR 构型目录等功能模型，供各服务启动初始化使用。（⚠️ 与 4.3.18 的边界需依据技术文档原条款明确，当前为代码内置生成）
